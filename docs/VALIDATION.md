# 首版验证记录

基准：Windows 11 25H2 x64，26200.6899；双 3840 × 2160 显示器，均为 150% 缩放，左屏原点为 -3840, 0。

## 0.1.4 关闭窗口后残留与崩溃

- 在修改生产逻辑前，通过独立进程测试窗口和管理器真实关闭按钮，复现 `LayoutCycleException / 0x802B0014`，与用户崩溃日志一致。此前 0.1.3 的窗口服务测试没有覆盖“源窗口销毁时，管理器仍在显示和布局卡片”的完整路径。
- 根因：DWM 源窗口失效后，`LayoutUpdated → UpdatePreviews → UpdatePreviewStatus` 每次布局都重新设置备用状态文字，反过来触发新的布局，卡片尚未移除就导致崩溃。
- 状态文字与可见性仅在值变化时设置；原生预览更新回调不再直接修改 XAML 状态，改为仅在可用性变化时排队更新，并忽略已经释放的卡片。未采用吞掉布局异常的处理。
- 新增 `-UiClose` 实机回归：七个独立测试窗口中六个通过真实关闭按钮的 Automation Invoke 路径关闭，一个从外部发送关闭请求；另验证应用第一次取消关闭时保留窗口、卡片和预览。移除后检查卡片脱离父容器、预览宿主消失、其他卡片对象保留；只操作本次创建的带唯一标记的窗口。
- 故意在刷新前保留已经失效的预览卡片，连续执行 20 次布局，状态稳定且无崩溃。关闭全部测试窗口后经过多轮轮询和布局，未残留卡片；USER 句柄从 69 降至 62。
- 32 项单元测试、原生关闭语义测试、隐藏初始化及可见交互回归通过。100 次隐藏预览注册/释放后 USER 句柄为 49 → 49；拖拽、菜单、设置型对话框期间的既有预览可见性检查继续通过。
- 回归报告：`artifacts/validation/ui-close-lifecycle-test.json`。按钮测试调用真实 Click 处理链路，未合成系统鼠标输入，也不代表所有第三方应用关闭行为均已验收。

## 0.1.3 悬停关闭按钮

- 卡片标题栏移至预览上方；悬停时右上角出现关闭按钮，键盘聚焦时也可见。按钮所在区域不与原生 DWM 预览重叠，点击不会触发卡片的窗口激活操作。
- 通过窗口服务发送异步 `WM_CLOSE`，发送前复核窗口身份；保留应用的保存提示、取消关闭及关闭到托盘行为，不结束进程。
- 独立窗口回归通过：正常关闭目标窗口、同应用其他窗口继续存在、应用可取消关闭、过期身份不发送关闭消息、取消条件解除后可正常关闭。
- 32 项自动化测试、隐藏初始化、关闭按钮悬停状态/布局检查及既有可见交互回归通过。没有为测试关闭用户应用。

## 0.1.2 拖放区域与密度

- 自动化测试增至 32 项；新增列数/卡片最小宽度、视口底部空白、分区边界和视口外拒绝接收测试。
- 显示器背景延伸至整个可见列表区域；拖放目标由完整视口中的横向分区决定，不再取决于窗口列表的实际高度。
- 取消不含 DWM 画面的默认 XAML 拖拽快照，增加独立 DWM 实时预览跟随鼠标；原卡片继续保持显示，拖拽结束/取消/收起时释放浮动预览。
- 可见 WinUI 回归通过：两个分区均为四列，分区底部目标匹配，浮动拖拽预览及原卡片同时可见；菜单、设置型对话框和提示生命周期回归继续通过。
- 隐藏初始化与 100 次资源生命周期检查通过，USER 句柄 56 → 56。
- 此处的拖拽检查直接运行管理器的拖拽预览与目标判断逻辑；实际鼠标拖放和浮动预览画面质量仍需目视确认，不以原生句柄可见性代替像素验收。

## 0.1.1 预览与交互修复

- 自动化测试增至 23 项；新增纵横裁剪、负坐标、留白区域和连续 2100 个滚动位置边界测试。
- 预览宿主按可见画面缩小，同时裁剪 DWM 源矩形；不再依赖 GDI 窗口遮罩。校正 `dwmapi.h` 要求的 45 字节结构体布局。
- 实机独立测试通过：滚动复用同一个原生宿主，宿主始终位于视口内，滚轮成功传回列表，最小化窗口成功注册并展示预览宿主，源窗口保持最小化且未被激活。此项不保证每个第三方应用都有可用的保留画面。
- 隐藏 WinUI 回归通过：标题变化、枚举顺序变化、跨显示器移动和单个窗口消失，都保留其他卡片及预览资源。100 次原生预览注册/释放后 USER 句柄为 54 → 54。
- 可见 WinUI 交互回归通过：12 个可见预览在拖拽状态、独立右键菜单及独立设置型对话框期间保持可见；成功、信息和警告不再弹出提示，错误提示持续显示。
- 拖拽状态测试验证预览可见性，不能替代实际鼠标拖放与画面流畅度的目视确认；新版滚动流畅度及所有第三方窗口的最小化画面仍需实际使用确认。

## 已修复并复验

首次集成测试发现最大化窗口仅更新恢复位置后，最大化框仍留在旧屏幕。实现已改为先在目标屏幕设置恢复位置，再恢复最大化，并校验最终状态；最小化窗口的显示器根据恢复位置识别。2026-09-21 完整集成测试复测通过。

修复了 XAML 主题资源解析错误，改用 WinUI 主题样式；修复了将私有第三方窗口移动接口用于管理器自身导致首次呼出中断的问题，自身窗口改用公开 IVirtualDesktopManager 接口。最新隐藏初始化检查和实际启动正常。

发布检查发现 unpackaged WinUI 的 `dotnet publish` 未自动复制应用 PRI/XBF 资源；工程已显式加入发布项，发布脚本会在打包 ZIP 前运行发布目录中的 EXE，初始化失败即停止打包。对应上游记录：[WindowsAppSDK #6720](https://github.com/microsoft/WindowsAppSDK/issues/6720)。

## 仍待补充的验收

界面工具重复报告应用身份绑定错误（将本程序映射为另一个已安装应用），因此停止重复尝试。缩略图与基本拖拽已由用户确认，以下项目仍待专项验证：

- 动态画面的刷新频率、WinUI 与原生缩略图的叠放、菜单遮挡和滚动裁剪。
- 分别核实鼠标拖拽的三条路径、悬停切换目标桌面和 Esc 取消。
- 全局快捷键、托盘、重复启动、浅色/深色外观的交互确认。
- 长时间可见预览的资源稳定性、Explorer 重启、物理显示器拔插及管理员/受保护应用。

隐藏初始化检查能确认原生缩略图关系注册成功，但不能证明画面实际正确显示或持续刷新。不得以此替代上述视觉验收。

## 复验入口
